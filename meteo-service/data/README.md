# Метеоаналитика Центрально-Лесного заповедника

Кейс 02 «Заповедного хакатона». Ядро сервиса: загрузка наблюдений,
контроль качества (qc_flag), правила полноты, суточные/декадные/месячные
таблицы и «среднее за выбранный период».

## Быстрый старт

```bash
uv sync                                  # окружение
# распаковать data/ из архива организаторов рядом с app.py
uv run streamlit run app.py              # веб-приложение
uv run python scripts/validate_coverage.py data   # сверка с эталоном
```

Данные ожидаются в каталоге `data/` из архива организаторов
(`data/ame60/ame60_ГГГГ.csv`, ...) рядом с `app.py`,
либо путь задаётся переменной `METEO_DATA_DIR`.

## Архитектура

```
src/meteo/
  loader.py     загрузка CSV в единую схему (станция из имени файла,
                отсутствующие параметры -> NaN; новые файлы того же
                формата подхватываются без правок кода)
  qc.py         apply_qc: dup_conflict -> удалить строку;
                "<параметр>:<причина>" -> NaN только в этом параметре
  coverage.py   daily_validity / monthly_coverage — правила полноты:
                АМЕ-60 >= 72 из 96 сроков; Сокол М1 >= 18 уникальных часов;
                месяц валиден при <= 10 невалидных днях и без серий >= 5.
                daily_validity(df, param=...) — полнота по одному параметру
                (давление Кр1-2024 проверяется по часам с валидным давлением)
  aggregate.py  daily_table / decade_table / monthly_table / period_mean
  aggregate.py  daily_table / decade_table / monthly_table / period_mean
  analytics.py  deviations_from_period (отклонения от «среднего за период»),
                diurnal_cycle (средний суточный ход),
                compare_glade_field (поляна Кр1 vs поле Кр2),
                wind_rose (роза ветров, 16 румбов)
  forecast.py   краткосрочный прогноз из Open-Meteo API (без ключа)
app.py          Streamlit-приложение: выбор станции/периода/параметра,
                вкладки «Таблицы и графики», «Отклонения от среднего»,
                «Поляна vs поле», «Роза ветров», «Прогноз»,
                загрузка нового файла наблюдений с проверкой формата
scripts/
  validate_coverage.py  сверка покрытия с coverage_by_month.csv (420 строк)
```

## Статус проверок (на наборе организаторов)

- Покрытие суток/месяцев совпадает с `coverage_by_month.csv` по всем
  **420 строкам** (все станции, 1992–2025).
- QC: 1 362 флага `pressure_hpa:range` у Кр1-2024 исключают только давление
  (t_air в тех же строках сохраняется); `wind_dir` АМЕ-60 за 2021 год
  исключён целиком по флагу; строки `dup_conflict` удаляются.
- Полнота давления Кр1-2024 по часам с валидным давлением:
  334 дня и 11 месяцев (апрель невалиден) — совпадает с README.
- Приложение прогнано тестовым раннером Streamlit: все вкладки
  (включая давление, декады, сравнение 2024/2025 и живой прогноз
  Open-Meteo) работают без исключений; 6 модульных тестов ядра — зелёные.
- Демо-факт для питча: июль 2010 теплее «среднего за 8 полных лет»
  на **+4,9 °C** (аномальная жара 2010 года) — отклонения работают
  и ловят реальные события.

## Жёсткие правила (не нарушать в UI и отчётах)

- Ряды АМЕ-60 и Сокол М1 **не объединять**, тренды через 2021/2022 не строить.
- Многолетнее среднее называется «среднее за выбранный период»,
  всегда показывать число лет.
- Время не округлять и не сдвигать под сетку.
- Декады: 1–10, 11–20, 21–конец месяца.
- Розу ветров не строить за 1998 (нет данных) и 2021 (недостоверны).

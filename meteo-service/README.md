# Метеоаналитика Центрально-Лесного заповедника

Кейс 02 «Заповедного хакатона». Решение состоит из двух частей:

1. **Python-пакет `meteo`** — вся логика обработки: загрузка наблюдений,
   контроль качества (qc_flag), правила полноты, агрегаты, аналитика.
2. **Статический HTML-отчёт** — один самодостаточный файл с интерфейсом:
   выбор станции/периода/параметра, таблицы, графики, отклонения,
   сравнение точек, роза ветров, прогноз. На каждой вкладке таблицу можно
   скачать в CSV или Excel с параметрами текущего расчёта. Отчёт работает
   офлайн двойным кликом (интернет нужен только вкладке «Прогноз»).

## Быстрый старт

```bash
uv sync                                              # окружение
# распаковать data/ из архива организаторов рядом с проектом
uv run python scripts/build_site.py data dist/index.html   # собрать отчёт
uv run python scripts/validate_coverage.py data      # сверка с эталоном
uv run pytest                                        # тесты ядра
```

Открыть результат: двойной клик по `dist/index.html`.

Данные ожидаются в каталоге `data/` из архива организаторов
(`data/ame60/ame60_ГГГГ.csv`, ...). **Новый файл наблюдений того же
формата** — просто положить в `data/` и пересобрать отчёт той же
командой: код менять не нужно (бонусная задача).

### Добавление новой станции

Каталог внутри `data/` может быть любым — поиск файлов рекурсивный. Важно
имя файла: `<station>_<year>.csv`, например `data/kr3/kr3_2025.csv`.
Идентификатор станции — латинские буквы/цифры без подчёркиваний. Новая
станция автоматически появится в отчёте как «Станция KR3 (годы)»; для неё
по умолчанию действует почасовое правило полноты Сокол М1 (18 часов).
Для новой 15-минутной станции типа АМЕ-60 нужно отдельно указать её `kind`.

Для демонстрации подготовлен синтетический двухлетний набор:

```bash
cp -r mock_data/kr3 data/
uv run python scripts/build_site.py data dist/index.html
```

В нём есть сезонный и суточный ход, пропуски, флаги параметров и
`dup_conflict`. Ожидаемый результат: KR3 (2024–2025), 724 валидных суток,
23 валидных месяца из 24; ноябрь 2025 невалиден из-за пяти дней подряд
без наблюдений.

## Архитектура

```
src/meteo/
  loader.py     загрузка CSV в единую схему (станция и год — из имени
                файла; новые станции и годы подхватываются автоматически;
                отсутствующие параметры -> NaN)
  qc.py         apply_qc: dup_conflict -> удалить строку;
                "<параметр>:<причина>" -> NaN только в этом параметре
  coverage.py   daily_validity / monthly_coverage — правила полноты:
                АМЕ-60 >= 72 из 96 сроков; Сокол М1 >= 18 уникальных часов;
                месяц валиден при <= 10 невалидных днях и без серий >= 5.
                daily_validity(df, param=...) — полнота по одному параметру
                (давление Кр1-2024 проверяется по часам с валидным давлением)
  aggregate.py  daily_table / pentad_table / decade_table / monthly_table /
                period_mean
  analytics.py  deviations_from_period (отклонения от «среднего за период»),
                diurnal_cycle (средний суточный ход),
                compare_glade_field (поляна Кр1 vs поле Кр2),
                wind_rose (роза ветров, 16 румбов)
  site_data.py  прогон контура по всем станциям -> JSON для страницы
web/
  template.html каркас отчёта: контролы, вкладки, JS-логика (Plotly.js),
                экспорт текущих таблиц в CSV/XLSX (SheetJS)
scripts/
  build_site.py         сборка dist/index.html (данные и Plotly.js встроены)
  validate_coverage.py  сверка покрытия с coverage_by_month.csv (420 строк)
```

Почему статический HTML, а не серверный фреймворк: вычислительно
тяжёлая часть (QC, полнота, агрегаты) всё равно делается в Python один
раз; отчёт — детерминированный снимок результата, который невозможно
«уронить» на демо: нет сервера, нет зависимостей, нет интернета.

## Статус проверок (на наборе организаторов)

- Покрытие суток/месяцев совпадает с `coverage_by_month.csv` по всем
  **420 строкам** (все станции, 1992–2025).
- QC: 1 362 флага `pressure_hpa:range` у Кр1-2024 исключают только давление
  (t_air в тех же строках сохраняется); `wind_dir` АМЕ-60 за 2021 год
  исключён целиком по флагу; строки `dup_conflict` удаляются.
- Полнота давления Кр1-2024 по часам с валидным давлением:
  334 дня и 11 месяцев (апрель невалиден) — совпадает с README.
- HTML-отчёт проверен рендером в headless-браузере: все вкладки
  (графики, отклонения, сравнение 2024/2025, роза ветров) отрисовываются;
  CSV/XLSX реально скачиваются и открываются на всех вкладках. Экспорт
  прогноза проверен с тестовым ответом Open-Meteo; 7 модульных тестов
  ядра — зелёные. Отдельно проверено автоматическое добавление KR3.
- Демо-факт для питча: июль 2010 теплее «среднего за период» почти
  на **+4,9 °C** (аномальная жара 2010 года) — отклонения ловят
  реальные климатические события.

## Жёсткие правила (не нарушать в UI и отчётах)

- Ряды АМЕ-60 и Сокол М1 **не объединять**, тренды через 2021/2022 не строить.
- Многолетнее среднее называется «среднее за выбранный период»,
  всегда показывать число лет.
- Время не округлять и не сдвигать под сетку.
- Декады: 1–10, 11–20, 21–конец месяца.
- Розу ветров не строить за 1998 (нет данных) и 2021 (недостоверны).
